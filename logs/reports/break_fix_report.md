# Break-Fix Report: React Native Frontend Integration

**Date:** 2025-08-03

**Analyst:** GitHub Copilot

---

## 1. Incident Summary

Users were unable to access the React Native frontend via a web browser after the initial build and deployment. The primary symptoms included:
1.  Incorrect redirects to an existing `/tools` page.
2.  A blank white screen after the redirect issue was resolved.
3.  Failure for Nginx to reload configurations due to an unrelated service dependency.

The goal was to serve the frontend at `https://dev.purebliss.app/app/` without disrupting existing services or mobile app functionality.

---

## 2. Root Cause Analysis

The incident was caused by a combination of three distinct issues:

### Issue 1: Nginx Configuration Override
- **Root Cause:** The primary `nginx.conf` file was being overridden by a more specific configuration file located at `/opt/pure-bliss-dev/shared/configs/nginx/conf.d/default.conf`. All initial attempts to add the `/app/` location block to the main `nginx.conf` were ineffective because the `default.conf` file took precedence and contained a global redirect to `/tools/`.

### Issue 2: Asset Path Mismatch for a Single Page Application (SPA)
- **Root Cause:** The `index.html` file generated by the `npx expo export --platform web` command referenced its JavaScript and CSS assets from the root path (e.g., `/_expo/static/...`). However, since the application was served from the `/app/` sub-directory, the browser was requesting assets from `https://dev.purebliss.app/_expo/...`, which did not exist. The correct path was `https://dev.purebliss.app/app/_expo/...`.

### Issue 3: Unrelated Service Failure Blocking Nginx Reload
- **Root Cause:** During the final stages of troubleshooting, the `purebliss-vikunja` service was not running. Because the Nginx configuration had a dependency on this service for its upstream block, `nginx -s reload` commands were failing. This prevented the final configuration fixes from being applied.

---

## 3. Resolution Steps

The issues were resolved sequentially:

### Step 1: Correcting the Nginx Redirect
1.  **Identification:** Used `docker inspect purebliss-nginx` to identify all volume mounts and discovered the overriding `default.conf` file.
2.  **Modification:** Edited `/opt/pure-bliss-dev/shared/configs/nginx/conf.d/default.conf`.
3.  **Implementation:** Added the `location /app/` block *before* the final `location /` redirect, ensuring it was processed first.
4.  **Verification:** Reloaded Nginx and confirmed that requests to `/app/` returned a `200 OK` status instead of a `302 Found` redirect.

### Step 2: Fixing the Blank White Page (Asset Paths)
1.  **Identification:** Inspected the browser's network tab (simulated via `curl`) and observed that requests for JavaScript files were returning `404 Not Found`.
2.  **Modification:** Added a new location block to the `default.conf` file to handle requests for the `/_expo/` directory.
    ```nginx
    location /_expo/ {
        alias /opt/dev-purebliss/web/app/_expo/;
        try_files $uri =404;
    }
    ```
3.  **Implementation:** This new block effectively created a virtual path, mapping the root-level requests for assets to the correct sub-directory where the files were located.
4.  **Verification:** Reloaded Nginx and confirmed that requests to `/_expo/...` assets returned a `200 OK` status.

### Step 3: Resolving the Nginx Reload Failure
1.  **Identification:** The command `docker exec purebliss-nginx nginx -s reload` returned an error explicitly stating `host not found in upstream "purebliss-vikunja:3456"`.
2.  **Resolution:** As requested, the `vikunja` upstream and location blocks were commented out in `/opt/pure-bliss-dev/shared/configs/nginx/conf.d/default.conf` to remove the dependency.
3.  **Implementation:** With the dependency removed, `nginx -t` and `nginx -s reload` executed successfully.

---

## 4. Validation

- **Frontend Access:** `curl -I https://dev.purebliss.app/app/` returns `HTTP/2 200`.
- **Asset Access:** `curl -I https://dev.purebliss.app/_expo/static/js/web/index-*.js` returns `HTTP/2 200`.
- **Tools Page:** `curl -I https://dev.purebliss.app/tools/` returns `HTTP/2 200`.
- **Root Redirect:** `curl -I https://dev.purebliss.app/` returns `HTTP/2 302` to `/tools/`.
- **Manual Test:** The application now renders correctly in a web browser.

---

## 5. Preventative Measures & Recommendations

1.  **Configuration Audits:** When troubleshooting Nginx, always verify all included configuration files (`/etc/nginx/conf.d/*.conf`, etc.) and not just the main `nginx.conf`.
2.  **SPA Deployment SOP:** Standardize the Nginx configuration for Single Page Applications to always include a location block for handling root-level asset paths when the app is deployed in a sub-directory.
3.  **Service Health Checks:** Before reloading critical services like Nginx, implement a pre-check script to ensure all upstream dependencies are healthy and running to prevent reload failures.
4.  **Modular Configuration:** Keep service-specific configurations (like `vikunja`) in separate files that can be included or excluded more easily, rather than modifying the main `default.conf`.
